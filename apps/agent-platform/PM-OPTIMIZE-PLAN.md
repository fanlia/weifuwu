# PM 优化计划（2026-12）——PM 审视发现缺口

> 来源：PM 全流程审视报告（4 类 Agent/15 页/全闭环实测）。
> 满足度 ~90%，剩余缺口按价值/成本排序实施。

## 缺口 → 计划（按实施顺序）

| # | 缺口 | 优先级 | 方案 | 成本 |
|---|---|---|---|---|
| 1 | **对话导出文件化**（当前仅 copyText 剪贴板） | P2 | Chat 导出生成 `.md` 文件下载（Blob）——「导出」按钮升级：复制 + 下载文件 | 小 |
| 2 | **KB 文档批量上传** | P3 | 上传 input 加 `multiple`——一次选多文件逐个上传 | 小 |
| 3 | **对话消息管理**（管理员删除任意消息） | P1 | messages 路由：DELETE 权限升级（sender 自己 + 管理员）；UI 消息 hover 显示删除 | 中 |
| 4 | **Dashboard 可视化**（CSS 柱条 → SVG 图表） | P2 | 自绘 SVG 折线/柱状（零依赖——趋势 + 留存 + 排行） | 中 |
| 5 | **Webhook 出站回调** | P1 | Agent 加 `webhook_url`（出站端点）+ `post_webhook` 工具（AI 主动推送）；入站应答可配置镜像到出站 | 大 |

## 验收标准

1. Chat「导出」出 .md 文件（含角色/时间/内容）——浏览器下载
2. KB 上传支持多文件选择
3. 管理员可删除任意消息；普通用户只能删自己的
4. Dashboard 趋势/留存 SVG 渲染（无 CSS hack）
5. Webhook Agent 配置出站 URL → AI 用 post_webhook 推送 → 外部端点收到带签名请求

## 裁剪声明

- Webhook 出站：一期「AI 主动推送」+「入站应答镜像」；不做出站签名强制（URL 私有即可）；
  推送重试 3 次指数退避（复用入站逻辑）
- 可视化：自绘 SVG（框架无 Chart 依赖——不引入 npm 包，FS-05）
- 消息管理：不做撤回他人消息（保留撤回=自己）+ 删除=管理员/自己

## 里程碑

| M2 | 消息管理（API + UI） |

| M4 | Webhook 出站回调（设计 + post_webhook 工具 + 测试） |
