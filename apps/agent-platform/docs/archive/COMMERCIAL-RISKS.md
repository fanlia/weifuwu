## 🔴 R1 租户隔离强制化（SaaS 生死线 · 最高优先）

**现状**：所有业务查询手写 `WHERE app_id = ${ctx.appId}`（抽查 agents/departments 均正确——但无中央强制，新查询漏写 = 泄漏）。

**目标**：隔离从"约定"变"强制"——漏写即报错，泄漏在开发期暴露。

**方案**：
1. **中央 SQL 拦截**（自研 pg 客户端能力）：识别租户表（agents/departments/messages/…白名单），查询无 `app_id` 条件且非豁免（系统表/统计聚合）→ 开发环境抛错、生产环境记录告警
2. **隔离审计测试**：遍历 `src/routes/*.ts` + `src/services/*.ts` 全部 SQL，静态断言含 app_id 条件（豁免登记：`_weifuwu_*` 系统表、纯聚合）
3. **requireApp 统一**：业务路由中间件统一调用（appId 注入 + 校验），消除手写差异

**验收**：
- [x] 审计测试扫描全部 SQL 零漏网（豁免清单透明 + 僵尸登记检测）——test/tenant-isolation.test.ts（3 测试全绿）
- [x] 故意删除某查询的 app_id → 测试红（验证有效）
- [ ] 中央 SQL 拦截（框架 pg 客户端——下一阶段）
- [ ] 生产日志无"未过滤租户查询"告警

## 🔴 R2 沙盒安全与负载（安全卖点加固）

**现状**：裸 Docker（512MB/1CPU/pids 256/--network none）；gVisor 仅登记；多租户共宿主机。

**目标**：威胁模型文档化 + 隔离可选加固 + 负载匹配真实场景。

**方案**：
1. **威胁模型文档**（`docs/sandbox-threat-model.md`）：明确"沙盒保护谁"（AI 不伤害租户/宿主）与信任边界（docker.sock 权限 = 管理员信任）
2. **gVisor 可选**：`SANDBOX_RUNTIME=runsc` 接通（已预留），文档说明取舍
3. **租户级资源配额**：容器资源（CPU/内存）按租户配置可调（agents 表加字段或租户级默认），避免"一个租户拖垮宿主机"
4. **宿主机容量监控**：池大小/容器数/内存水位 → ops 接口 + 告警日志

**验收**：
- [x] 威胁模型文档（docs/sandbox-threat-model.md——信任边界/攻击面/残余风险/裁剪）
- [x] `--cap-drop ALL` + `--security-opt no-new-privileges` 容器加固（文档核对时发现缺口即补）
- [ ] runsc 运行时实测跑通（需安装）
- [ ] 租户资源配额可配置 + 超配保护

## 🔴 R3 计量收口（计费公平）

**现状**：`agent_logs` 仅 AI 回复两点写入；KB 检索（embedding）、Webhook、预览不计入配额。

**目标**：所有 LLM/embedding 消耗统一计量，配额/成本/ROI 口径一致。

**方案**：
1. **统一计量中间件**：`ctx.ai.chat/stream/agent` + `ctx.ai.embed/embedMany` 调用统一走 `meter.ts`（记录 tokens/app_id/agent_id/场景）
2. **场景维度**：回复 / KB 检索 / Webhook / 预览——全部扣配额，配额检查点统一
3. **多模型单价表**：ROI/成本按实际模型单价（BYOK 租户用自己的价目或估算）
4. **配额语义**：流式中途超限 → 完成当前回复但标记（不中断体验）；发送时检查保留

**验收**：
- [x] KB 检索计量（agent_logs 记录调用）+ 配额拦截（到期/超限不检索）
- [x] Webhook 配额拦截（到期/超限 → 402，先于签名验证）
- [x] 实测：demo 到期 → Webhook 402「免费版试用已到期」
- [ ] 预览计入（裁剪：测试功能不计费——诚实登记）
- [ ] ROI 成本按模型单价计算（非统一假设）

## 🟠 R4 权限模型 V2（企业采购门槛）

**现状**：owner/member + 部门 admin/member 两级；无数据权限；HITL 审批仅部门 admin。

**目标**：角色能力矩阵 + 数据可见性 + 审批兜底。

**方案**：
1. **角色能力矩阵**（permission 表或代码声明）：
   - owner：全部 + 计费/删除租户
   - admin：建 Agent/配知识库/部门管理/审批
   - member：对话/使用已授权 Agent
   - 新增 `viewer`（只读——老板看板/审计合规角色）
2. **数据可见性**：部门级对话可见性（member 仅自己参与的部门——配置项）
3. **审批兜底**：部门无 admin 时 → 升级租户 owner 可批
4. **API 校验收敛**：`requirePermission(action)` 中间件替代散落检查

**验收**：
- [x] 权限矩阵文档（docs/permissions.md——角色定义/能力矩阵/实现位置/边界登记）
- [x] viewer 端到端：邀请选角色 → 查看 200 / 发消息 403 / 建 Agent 403 / 建部门 403
- [x] requireWriter/requireDeptManager 收敛（permissions.ts——审批兜底 owner 既有）

## 🟠 R5 层级模型（企业-子租户）

**现状**：注册即租户，无"企业下开子租户"；IDEA.md 的 company 概念已删。

**目标**：企业账户（enterprise）→ 子租户（team/company）两级，统一结算。

**方案**：
1. **enterprise 表**：企业账户（结算主体）+ 绑定多个 app（子租户）
2. **管理员开子租户**：/admin 建租户时可选归属企业（复用 G2 管理后台）
3. **统一结算视图**：企业级用量聚合（子租户汇总）——管理 API v1 扩展
4. **兼容**：既有 app 无 enterprise = 独立租户（不破坏现有）

**验收**：
- [ ] 企业建 2 个子租户 → 企业用量视图正确
- [ ] 既有租户不受影响（回归）

## 🟠 R6 AI 质量反馈闭环（留存根基）

**现状**：无点赞/点踩；HITL 只批不改（不能编辑草稿）；无 RAG/工具质量指标。

**目标**：反馈 → 改进 → 可衡量的质量循环。

**方案**：
1. **消息反馈**：AI 回复下点赞/点踩（messages 表加字段）→ 汇总视图（运营/owner 看质量）
2. **草稿编辑**：HITL 草稿可编辑后发布（不只是批准原文）——审批页加编辑框
3. **质量指标**：工具调用成功率、沙盒失败率、RAG 无命中率 → Dashboard/管理后台
4. **反馈数据导出**：审计/CSV 含质量字段（续费谈判证据）

**验收**：
- [x] 点赞/点踩端到端（messages.feedback + API + Chat 页按钮 + stats 汇总）——实测 like ✓
- [x] 草稿编辑发布流程（PUT /api/messages/:id/draft + Approvals 编辑框 + 审计）——实测修订 ✓
- [x] 质量指标：toolSuccessRate（agent_logs success 聚合）+ likes/dislikes（stats.quality）
- [ ] RAG 无命中率（需检索场景标记——登记待做）

## 🟠 R7 私有化交付链（签单后不翻车）

**现状**：Dockerfile + backup/restore 脚本；无升级路径/部署文档/告警。

**目标**：交付包 = 部署 + 升级 + 运维三件套。

**方案**：
1. **部署文档**：Docker Compose 一键（pg + redis + app + 可选沙盒）+ 环境变量清单
2. **升级脚本**：`scripts/upgrade.mjs`——备份 → migration → 启动校验 → 回滚点
3. **版本化 migration**：schema 版本表（当前是 CREATE IF NOT EXISTS 追加式——升级安全但需验证）
4. **健康告警**：healthz 扩展（pg/redis/沙盒/磁盘）→ 失败邮件/webhook 通知（复用 email 中间件）

**验收**：
- [x] docker-compose.yml 一键部署（pg+redis+app + 卷 + 健康检查 + 环境变量全表）
- [x] 升级脚本 scripts/upgrade.mjs（pg_dump 备份 → 重建 → healthz 轮询 → 失败回滚指引）
- [x] healthz 扩展（disk 水位 + version）+ 告警接入文档（cron + 邮件/webhook + 阈值表）
- [x] docs/deployment.md 交付三件套（部署/升级/运维）

## 🟡 R8 BYOK 定价模型

**现状**：BYOK 租户自带 Key，平台不赚模型差价。

**方案**：
1. **定价文档化**：BYOK = 平台功能费（席位）+ 服务费；Pro = 模型代购加价
2. **区分标记**：租户计划显示"BYOK"徽章；管理后台按计费模式筛选
3. **成本视图适配**：BYOK 租户 ROI 用其自有单价（与 R3 联动）

**验收**：定价文档 + 管理后台计费模式列。

## 🟡 R9 可观测性

**现状**：x-trace-id/审计有；无指标面板/告警/容量。

**方案**：
1. **指标接口**：/api/metrics 扩展（请求量/延迟/错误率/AI 调用/沙盒池）——Prometheus 格式
2. **容量水位**：沙盒池/宿主机内存 → 管理后台视图
3. **告警规则文档**：阈值建议（池满/错误率/磁盘）

**验收**：[x] /api/metrics/prom（Prometheus 文本格式——uptime/请求/错误/AI/沙盒/磁盘）实测可抓；[x] Admin 容量卡（沙盒池/模式/镜像）。

## 🟡 R10 合规

**现状**：无 GDPR 删除级联；AI 输出无责任说明。

**方案**：
1. **用户删除级联**：删除用户 → 匿名化消息/日志/审计（保留聚合统计，去标识化）
2. **数据导出补全**：用户数据导出（消息/知识库/配置）——已有审计导出，补全量
3. **合规文档**：数据处理说明（存储/保留期/删除流程）——销售材料附件

**验收**：删除用户端到端（无孤儿 PII）；数据导出可用。

## 🟡 R11 竞争叙事收窄

**现状**：功能多但叙事宽（打不过大厂免费）。

**方案**：
1. **主叙事**：私有化 + 沙盒安全 + 审批治理（"AI 干活但可控"）
2. **场景聚焦**：S1 知识库 + S3 研发辅助（两个最能打场景）做深
3. **对比材料**：vs 钉钉 AI/Coze 差异表（沙盒/审批/私有化/数据自主）

**验收**：销售一页纸 + 场景 demo 脚本。

## 优先级路线图

```
Phase A「不泄漏不死」（R1 + R3 + R2）——安全/计量/沙盒 · 2-3 周
  → SaaS 生死线：隔离强制 + 计量收口 + 沙盒加固

Phase B「能交付能续费」（R7 + R6 + R4）——交付链/质量/权限 · 3-4 周
  → 私有化交付三件套 + 反馈闭环 + 权限矩阵

Phase C「能变大单」（R5 + R9 + R10 + R8 + R11）——层级/运维/合规/定价 · 按需
  → 企业-子租户 + 可观测 + GDPR + 叙事收窄
```
