## 1. 波次计划

### 波次 1：无效部门显式错误态（P2——小而独立）

- **Chat 组件 404 分支**：loadMessages/loadMembers 捕获 404 →
  `$.deptMissing = true` → 渲染显式错误态（「部门不存在或无权访问」
  + EmptyState + 「返回会话列表」按钮）——替代静默空态
- **区分语义**：404 = 错误态（本波次）；200 空 = 真空态（AI 待命间等
  引导文案不动）
- **防线**：UI 测试——无效 id 直开 /chat/:id 断言错误文案 + 返回按钮可用；
  有效空部门回归（空态文案不变）
- 验收：直链无效 id 不再误导

### 波次 2：HITL 快捷确认按钮（P1 主体——数据面到交互面）

AI 确认型提问（「请确认清理范围？」）渲染为可点击选项 chip——点击即发送：

- **输出约定**：AI 确认型提问在回复末尾输出
  `[[choices:清理 30 天前备份|全部清理|暂不清理]]`（行内标记——
  persona 层追加一句格式指引，非强制 schema——渐进增强）
- **服务端解析**（chat.ts 流结束收敛处）：
  正则剥离 `[[choices:...]]` → content 保持干净 → 解析出
  `quick_replies: string[]`（上限 4 项、单项 ≤ 20 字符裁剪）→
  存 `messages.quick_replies`（新 JSONB 列——迁移 `ADD COLUMN IF NOT EXISTS`）
  → `emitWf({ type:'wf:done', ..., quickReplies })`（done 载荷扩展）
- **前端渲染**（MessageItem 气泡尾部）：AI 消息 + `quick_replies` 非空 →
  chip 行（按钮样式、hover 反馈）；点击 = 回填输入框并直接发送
  （复用 sendText——发送后本消息 chip 置灰/隐藏——已答不重复答）
- **兼容**：旧消息无列值 → 无 chip；AI 未输出标记 → 无 chip（零影响）；
  刷新后从 GET messages 读列值恢复 chip（已答复消息不恢复——以是否存在
  后续同 sender 用户消息判断，或 chip 仅对「最后一条 AI 消息」渲染——取简）
- **防线**：
  - 解析单测（services 层——标记剥离/上限裁剪/无标记透传/多行容错）
  - 前端渲染契约（seed 消息直插 quick_replies——chip 渲染 + 点击发送
    + 已答隐藏；DB seed 不依赖真实 LLM 输出）
- 验收：走查复测——AI 确认型提问出现可点选项，点击即答
- **判负预登记**：前端启发式检测（正则匹配「请确认/？」渲染通用按钮）——
  误报高且按钮文案无从生成——判负；选项必须来自 AI 结构化输出

## 3. 判负预登记

| 项 | 判负理由 | 推翻条件 |
| --- | --- | --- |
| 前端启发式检测确认型提问 | 正则「请确认/？」误报高（「你确认过吗」也命中）；无 AI 参与无法生成按钮文案 | — |
| 选项强制 schema（structured output） | 现有 LLM 链路为纯文本流——强制 JSON schema 需换响应格式，成本/风险大于收益；行内标记渐进增强已够 | 切换支持 structured output 的模型 |
| 通用交互组件（问卷式表单/滑杆等） | 单一场景（确认选择）不需要通用表单引擎——chip 行最小 | 出现多种结构化交互需求 |
| 走查流畅面（@定向/编排链）固化端到端测试 | 依赖真实 LLM 输出——不可确定性断言（判负）；确定性面（chip 渲染/404 错误态）已在本计划锁定 | 出现确定性注入手段覆盖编排链 |
