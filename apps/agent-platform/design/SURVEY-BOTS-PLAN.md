# SURVEY-BOTS-PLAN · 「10 机器人填问卷」场景满足计划

> 2027-09 制定（现状审计先行——不臆想需求）——apps/agent-platform。
> 场景：**模拟 10 个机器人填写问卷**（演示/测试/数据生成三用途）。
> 完成状态：⬜ 待执行

---

## 一、现状审计（诚实告知——已有成熟交付）

**该场景平台已有一整套「AI 真填档」交付（2026-12 新架构）：**

| 件 | 位置 | 说明 |
| --- | --- | --- |
| 10 人设种子 | `scripts/seed-survey-agents.mjs` | 财务小王/市场小李/产品老张/客服小陈/研发大刘/人事小周/销售阿强/运营小赵/行政陈姐/实习生阿泽——各独立部门（独立沙盒并发）——人设 prompt（年龄/态度/评分倾向/语气） |
| 一键派单 | `POST /demo-survey/launch` | 服务端并发派单（BATCH=3 · 批间 10s——连接池/容器启动峰值控制——45s 池满事故防线）——@角色 触发——`{ success, sent, roles }` |
| 角色填写链 | agent-browser（沙盒内） | open 问卷 → snapshot 读题 → fill/select/check 作答 → submit → 结果写工作目录 `survey-result.json`（交付物）→ close |
| 实时统计 | `/demo-survey/stats` + WS `/survey-live` | 逐题答案流/提交计数/在线数/来源列表——统计页实时跳动 |
| 生产验收 | `scripts/survey-acceptance.mjs` | 终态断言：10 提交 + 在线归零（10 分钟超时） |
| 辅助 | survey-launch / survey-summary / survey-demo | 派单/汇总/演示辅助 |

**缺口（本轮需求的落点）：**

1. **无轻量确定性档**——模拟 = 只能用 AI 真填（LLM + 沙盒 + 浏览器——10 分钟级——每次 10 容器 + 10 × LLM 调用——**演示节奏重 / 有成本 / 不可控**）
2. **验收依赖 LLM**——角色答错/卡住 → 超时失败——**不可作问卷系统的 CI 回归**（问卷本身改动的验收被 AI 不确定性绑架）
3. **可重复性弱**——同 seed 不同次答案漂移（LLM 采样）——数据生成不可复现

**协议面勘查结论（模拟器可行性）**：WS `/survey-live` 为完整协议面（`survey:hello/answer/submit/bye` + 服务端广播 `state/online/submitted`）——**无来源唯一性校验**（source 即字符串标识）——**协议级客户端可直接完成全部交互**——统计页/验收脚本的观测面对模拟器同样成立。

## 二、需求拆解——双档形态

| | **A 档：AI 真填（已有）** | **B 档：协议模拟（本计划新增）** |
| --- | --- | --- |
| 机器人 = | LLM 人设 agent（沙盒浏览器真操作） | 10 个 WS 客户端（协议面完整交互） |
| 时长 | 10 分钟级（分批错峰） | 30 秒级（人类节奏可加速） |
| 答案 | 人设驱动（LLM 采样——多样真实） | 人设模板（答案倾向提炼——确定性） |
| 成本 | 10 容器 + 10 × LLM | 零（纯 WS） |
| 用途 | 演示「AI 真实填写」（能力面） | 演示/回归/数据生成（稳定面） |

**两档观测面同一**（统计页/验收断言/在线与提交流）——A/B 互补不互斥。
**注意**：两档勿并发（提交计数合并——不同 source 即可——同源重复会顶号）。

## 三、波次计划

### 波次 1：协议级机器人模拟器（核心）⬜
`scripts/simulate-survey-bots.mjs`（B 档主体）：
- WS `/survey-live` 直连——hello → 逐题 answer（完整性：5 题——年龄/行业/关注/评分/反馈）→ submit → 短停顿 → bye
- **10 人设模板**（从 seed prompt 提炼确定性分布——财务小王低分聚焦性价比/市场小李高分热情/研发大刘 3-4 保守/客服小陈看响应/实习生青涩……——每题可复现：`--seed=42`）
- **人类节奏**（`--pace=human` 每题 0.8-2.5s 随机 / `--pace=fast` 0.1-0.3s——演示两态）
- 参数：`--bots=10 --race=1.2s --pace=human --seed=42 --base=WS_URL`（默认读 env）
- 完成报告：提交数/顺序/峰值在线（统计页同源数据自证）

### 波次 2：确定性验收集成（CI 可挂）⬜
- `survey-acceptance.mjs` 加 `--mode=sim`：前置跑模拟器（B 档）→ 同终态断言（10 提交 + 在线归零 + 提交顺序完整 + 峰值 ≤ 预期）
- **问卷系统回归解耦 LLM**——服务端每题断言（survey:answer 流完整——5 题 × 10 角色全收）
- A 档验收保留（`--mode=llm` 默认——生产真验）

### 波次 3：展示路径（发现性）⬜
- 统计页加「模拟填写」按钮（一键启动 B 档——demo 演示即点即有——**与 launch API 并列**）
- README/脚本头注释双档使用路径一句话
- **判负考察点**：若按钮加面 > 脚本面收益——只做文档（脚本独立可跑——不加 UI）

### 波次 4：验收与归档 ⬜
- 模拟器 10 并发实测（统计页快照：10 来源/提交顺序/在线归零——与 A 档验收同一观测）
- 全量回归（既有测试无涉 survey——聊胜全跑 UI 无关面）
- 计划归档（完成标记 + 提交锚点）

## 四、判负预登记
- **AI 档稳定性增强**：无失败实证（验收超时=上限设计——非已知故障）——B 档稳定后 A 档真问题自显——**需求驱动再修**
- **launch API 集成 B 档**（`mode=sim`）：模拟器独立脚本面足够——**不加服务端面**（除非演示按钮需要——波次 3 定论）
