# AI 人格化计划（PERSONA-PLAN）——AI/人可替换的群协作体验

> **状态**：2026-12 建立——P0 ✅ · P1 ✅（含 P1-3 附件上传）· P2 ✅（纪律+角标）· P3 ✅（组织角色）· P4 待做
> 北极星验收：替换测试/盲测待 P4 后整体跑
> 用户决策方向：先研究"没有 AI 时真人团队如何在群聊协作"，
> 提炼隐性社会协议，把某人替换为 AI 后**体验不变**。
> **核心原则**：AI 不是"更聪明的对话机器人"，而是**遵守同一套社会协议的群成员**。
> **验收北极星**：盲测一段群对话，人分不清哪个成员是 AI；把真人替换成 AI 后协作流不变。

---

## 1. 愿景

群聊中的每个成员——无论是人还是 AI——都遵循同一套成员协议：

```
成员协议 = 身份（我是谁/能干什么）
        + 语境（我看到什么/谁在说/回的是哪条）
        + 行为（收到/认领/移交/汇报/失败明说/分歧给理由）
        + 社会性（称呼/致谢/道歉）
        + 角色（谁是我老板/谁能批/报告给谁）
        + 记忆（我承诺过什么/上次说过什么）
```

**可替换**：把"财务小王"换成"AI 财务助手"，群里其他人无感知——@他、他认领、他移交、他汇报、他道歉，全部一样。

## 2. 现状盘点（架构基础已具备）

| 能力 | 现状 | 说明 |
|------|------|------|
| 统一成员模型 | ✅ | 人（user agent）与 AI（ai agent）同在 `department_members`，消息 `sender_id` 均指向 `agents` |
| 身份字段 | ⚠️ | name/avatar/description 已有；**缺角色标签/专长**（人一眼知道"财务小王"，AI 没有） |
| 发信人署名 | ❌ | 历史查询取了 `sender_name` 但未注入 chatMessages——AI 看到无署名消息流 |
| 引用上下文 | ❌ | messages 表有 `reply_to` 字段但 AI 上下文未注入原文 |
| 同事认知 | ❌ | **最大缺口**——AI 只认识自己，不知道部门里还有谁、各擅长什么 |
| 协作话语 | ❌ | 无认领/移交/汇报/失败明说纪律——AI 只会"好的，我处理" |
| 委托能力 | ⚠️ | call_agent 已有（深度 2 防环 + agent_logs 审计），**缺委托背景注入** |
| 社会性 | ❌ | 无称呼/致谢/道歉纪律 |
| 组织角色 | ❌ | AI 不知道群里谁是老板、谁能批 |
| 记忆 | ⚠️ | agent_memories 个人记忆已有；**缺群共识摘要**（P4） |

## 3. 成员协议模型（五层）

```
┌─ L0 身份层：角色标签/专长/头像——人看到"AI 是谁"（前端 + 注入）
├─ L1 语境层：署名/引用/同事名单——AI 看到"人看到的世界"
├─ L2 行为协议层：协作话语/社会性/分歧纪律——AI 像人一样说话做事
├─ L3 角色层：组织角色注入——AI 有权限直觉（谁批/报告给谁）
└─ L4 记忆层：个人记忆（已有）+ 群共识摘要（待做）
```

## 4. 分阶段实施计划

### P0 身份层——AI 在群里"有人设"（小，先做）

**任务 P0-1：agents 表加角色字段**
- `schema.sql` migration：`role_label TEXT`（如"财务分析"）+ `expertise TEXT`（如"Excel/报表/预算"）
- Agent 配置页（NewAgent/AgentDetail）加两个输入框
- 群成员列表（DepartmentDetail 成员展示）+ 消息里 AI 回复前缀展示角色标签
- **TDD**：字段读写、配置页保存、成员列表返回新字段

**任务 P0-2：同事名单注入**
- runAllAgents 查部门全部成员（人 + AI 的名字/类型/role_label/expertise）→ 注入每个 AI 的 systemPrompt：
  ```
  【本部门成员】
  - 王总（人，admin）：老板——需求发起人/最终决策人
  - 财务助手（AI）：财务分析——Excel/报表/预算
  - 产品知识库（AI）：产品资料检索
  协作规则：需要专业协助时用 call_agent 委托；人 @ 你时必须响应。
  ```
- **TDD**：注入内容断言（含成员清单 + 角色标签）

**验收 P0**：群成员列表看到 AI 的专长标签；问 AI"这个群里都有谁？"能正确回答。

### P1 语境层——AI 看到人看到的世界（核心，先做）

**任务 P1-1：发信人署名注入**
- chat.ts 历史构建处：`content: `[${msg.sender_name}] ${msg.content}``
- AI 回复自动带称呼（结合 P2 纪律）
- **TDD**：历史消息注入断言（user/ai 都署名；系统消息跳过）

**任务 P1-2：reply_to 引用上下文**
- 历史查询 join messages 取 reply_to 原文 → 注入 `（回复 [王总] "原文…"）`
- **TDD**：引用消息注入断言

**任务 P1-3：聊天附件上传**（沿用上轮设计，见 COMMERCIAL 演进）
- 上传 → 落工作空间 `uploads/{msg_id}/` + attachments JSONB + 附件清单注入
- 配置页工作空间上传（复用公共校验模块）
- **TDD**：白名单/大小/消毒/注入/跳过 KB

**任务 P1-4：委托背景注入**
- call_agent：B 收到的消息带 `[被 {A} 委托，原始任务：{当前用户消息摘要}] {message}`
- **TDD**：委托时 B 上下文含委托链信息

**验收 P1**：对话里 AI 知道谁在说、回的是哪条、文件在哪、被谁委托。

### P2 行为协议层——AI 像人一样说话（提示模板统一）

**任务 P2-1：统一协作纪律模板（`src/services/persona.ts` 新模块）**
- 提取 `buildPersonaLayer({ agent, departmentCtx })` → 返回统一注入段，所有 AI 共用（chat.ts 三处 systemPrompt 拼接点收敛到一处）
- 纪律内容（一段话协议）：
  ```
  【协作方式】你是本群的一员，像同事一样协作：
  1. 收到任务先确认（"好的王总，我来"），需要专业协助时用 call_agent 委托
  2. 任务进行中同步进度；完成时汇报结果（带数据出处）
  3. 失败必须明说（"数据不全，缺 X"）并给出补全路径
  4. 看到其他成员回复与你的认知不一致时，显式说明分歧点
  5. 称呼对方（[名字]）、致谢、犯错道歉——像真人同事一样
  ```
- **TDD**：persona 模块输出断言（含纪律全文 + 动态部分拼接）

**任务 P2-2：认领/移交/汇报话语识别（前端轻量）**
- 前端检测 AI 回复中的"我来/认领/已完成/移交/交给"→ 消息卡片打状态角标（📋 进行中/✅ 已完成）
- 纯前端展示，无任务实体（**体验不变 = 对话流即协作流，不做任务系统**）
- **TDD**：识别函数单测（正则覆盖认领/移交/汇报话语）

**验收 P2**：一段群对话（王总→财务助手→知识库→小码）无违和感，盲测分不清 AI/人。

### P3 角色层——AI 有权限直觉

**任务 P3-1：组织角色注入**
- 部门成员 admin（王总）→ AI 知道"王总是老板：决策/审批找他；我是他的下属"
- 审批场景：HITL 待批时提示"已提交王总审批"
- **TDD**：注入断言 + 审批提示文案

**任务 P3-2：角色模板**（可选，登记）
- "老板替身"（秘书型：汇报/提醒/审批转达）、"员工替身"（执行型：认领/汇报）
- 依赖 P0 角色标签，客户需求驱动再细化

**验收 P3**：问 AI"这件事谁能批？"能答"王总"；AI 报告对象正确。

### P4 记忆层——群共识（登记待做，不排期）

- 群级摘要：每 N 条消息生成群共识摘要（任务/决定/待办）→ 注入上下文
- 依赖：群消息量大后才有价值；C1 断点续跑同批登记
- **诚实裁剪**：不做——agent_memories 个人记忆先跑，群摘要等真实客户群规模数据驱动

## 5. 可替换性验收（北极星测试）

| 测试 | 方法 | 通过标准 |
|------|------|---------|
| **替换测试** | seed 建"财务部"：真人财务小王 vs AI 财务助手，同一任务序列（分析→委托→汇报→补充→修正）各跑一遍 | 两轮对话的协作流结构一致（认领/移交/汇报/道歉点对齐） |
| **盲测** | 混合人/AI 回复的对话给人看，标注"哪个是人" | 正确率 < 60%（猜不出） |
| **协议回归** | 单测断言注入内容（署名/名单/引用/委托背景/纪律全文） | 全绿（防漂移） |
| **实测** | agent-browser 群聊实测：@财务助手 上传 Excel → 认领 → 委托知识库 → 汇报带出处 | 全程无人工干预 |

## 6. 实施顺序与依赖

```
P0（身份）→ P1（语境）→ P2（协议）→ P3（角色）→ P4（记忆，待做）
P0-2 依赖 P0-1（角色字段）；P1 独立可并行；P2-1 依赖 P1-1（署名）
P2 完成后即可跑替换测试 + 盲测（北极星验收）
```

**每阶段独立可演示**：P0 完=群里有"人设"的 AI；P1 完=AI 看得懂群；P2 完=AI 像同事；P3 完=AI 懂组织。

## 7. 诚实裁剪（登记）

- ❌ 不做任务实体系统/任务卡片（对话流即协作流——真人也没有任务板）
- ❌ 不做自动编排器（orchestrator 自动拆解分发——不可控）
- ❌ 不做群共识摘要（P4 待做，等真实群规模）
- ❌ 不做 AI 间共享记忆库（agent_memories 各自独立——保持隐私边界）
- ❌ 不做情绪模型/性格系统（人格化 ≠ 情绪化——纪律与分寸优先）
