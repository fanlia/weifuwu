# 沙盒威胁模型（Sandbox Threat Model）

> **状态**：📋 2026-12 建立——安全销售材料 + 加固基线
> **范围**：agent-platform 的 Docker 沙盒执行环境（文件工具/命令执行的隔离边界）

---

## 1. 一句话

> 沙盒保护的是**租户与宿主**（AI 的行为被限制在容器内），不是"AI 本身"——
> 容器逃逸防范依赖内核与 Docker 配置，这是管理员信任边界的一部分。

## 2. 信任边界（谁防谁）

```
┌─────────────────────────────────────────────────────┐
│ 宿主（host）——管理员信任域                            │
│   · Docker 守护进程（docker.sock 权限 = 管理员）       │
│   · 工作空间卷（data/workspaces/——状态真相源）        │
│  ┌───────────────────────────────────────────────┐  │
│  │ 沙盒容器（ap-sandbox-{agent_id}）              │  │
│  │   · --network none（默认）→ 无网络出站          │  │
│  │   · 内存 512MB · 1 CPU · pids 256              │  │
│  │   · 非 root node 用户                          │  │
│  │   · 文件仅限 /ws（bind mount 卷）              │  │
│  │   · 工具执行器 tool-runner.js（stdin/stdout）   │  │
│  └───────────────────────────────────────────────┘  │
│  · AI 模型（外部 API——数据出域由 BYOK/全局 key 决定）  │
└─────────────────────────────────────────────────────┘
```

**信任链**：
- **管理员信任 Docker 守护进程**：docker.sock 的持有者（服务进程）可执行任意容器操作——沙盒保护 AI/租户，**不保护管理员自己**
- **租户信任沙盒**：租户的 AI 操作被容器限制，不能读宿主文件/访问内网/耗尽资源
- **宿主信任租户**：多租户共宿主时，A 租户的容器不能影响 B 租户（依赖容器隔离 + 资源配额）

## 3. 攻击面与缓解

| 攻击面 | 风险 | 缓解 | 残余风险 |
|--------|------|------|---------|
| 容器逃逸（内核漏洞） | AI 命令执行逃出容器 | 非 root 用户、seccomp 默认、资源限制 | 低概率（内核 0day）；可选 gVisor（`SANDBOX_RUNTIME=runsc`）加固 |
| 路径穿越 | AI 读写 /ws 外文件 | tool-runner.js 限制在 /ws；卷独立 | 工具执行器本身是信任代码 |
| SSRF（出站） | AI 请求内网/元数据 | `--network none` 默认；「允许网络访问」显式开启 | 开启网络后无出口过滤（桥接网络） |
| 资源耗尽 | AI 死循环占满 CPU/内存 | 512MB/1CPU/pids 256；池上限 20；空闲 600s 销毁 | 单容器资源上限内仍可影响同宿主（容量规划职责） |
| 数据残留 | AI 在容器写敏感数据 | 容器销毁（幂等重建）；文件在卷（可见可清理） | 卷内数据保留（业务设计——工作空间文件） |
| docker.sock 泄露 | 攻击者拿到服务进程权限 | socket 权限受控；服务只做白名单容器操作 | 服务漏洞 = 宿主沦陷（纵深：最小权限运行服务） |

## 4. 已知裁剪（诚实登记）

- **gVisor 可选未默认**：`SANDBOX_RUNTIME=runsc` 已预留，默认 runc——加固需安装 runsc 并验证工具链
- **网络出口无过滤**：允许网络访问 = 全部出站（无域名/端口白名单）
- **无每租户资源配额上限**（当前全局统一 512MB/1CPU）——多租户容量隔离待做（R2-3）
- **无沙盒审计日志导出**（容器内命令历史在 agent_logs，但无逐命令审计导出）

## 5. 运维建议（交付文档配套）

1. **生产必配**：Docker 只读根文件系统、seccomp 严格模式、`--cap-drop ALL`（当前默认）
2. **高安全客户**：启用 gVisor + 每租户配额 + 网络白名单
3. **监控**：容器逃逸迹象（主机异常进程/挂载）、资源水位（池/内存/CPU）
4. **升级**：Docker/内核安全补丁跟踪；容器镜像（node:24）定期重建
