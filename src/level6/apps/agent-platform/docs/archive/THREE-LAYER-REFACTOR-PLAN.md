# 三层模型重构方案（agent-platform 全应用）

> **基础**：三层统一模型已落地（部门=工作目录 · sandbox=计算资源 · agent=能力——含单聊特例、DB 驱动生命周期、配额/预算/指标）。
> **目标**：UI 从「管理后台」重构为「项目空间工作台」——让三层模型的架构优势变成用户可感知的体验。
> **视角**：老板 / 用户 / 产品经理 / 运营经理 / 视觉设计师 / 产品设计师 / 前端开发者 / 后端开发者。
> 纪律：红→绿逐项验证；行为变更先查旧测试（CS-06）；UI 测试基线扩展（pages.test.ts）。

## 一、现状审计

### 1.1 架构层（已落地 ✅——重构的地基）

| 层 | 现状 | 状态 |
|----|------|------|
| 部门 | 工作目录（workspace_path）+ 成员（department_members）+ 文件浏览器 + 沙盒卡片 | ✅ 已实现 |
| sandbox | DB 驱动生命周期（requested→running⇄stopped→terminated）+ 两级回收 + reconcile + 配额/预算/指标 | ✅ 已实现 |
| agent | 纯能力（提示词/工具/技能/记忆）——加入部门即获得该部门目录/环境 | ✅ 已实现 |
| 工具链 | 全工具容器化（tool-runner）+ ap-sandbox:latest（python/office/agent-browser）+ 孤儿进程根治 | ✅ 已实现 |

### 1.2 UI 心智层（重构的对象——架构与体验的差距）

| 差距 | 现状 | 后果 |
|------|------|------|
| **信息架构按管理对象组织** | 导航：概览/聊天/审批/Agent/沙盒/模板/部门——沙盒、Agent 是主角 | 用户要先理解概念才能干活；三层模型藏起来了 |
| **聊天与部门分离** | Chat.tsx（686 行单体：消息/工具状态/HITL/搜索）与 DepartmentDetail（成员/文件/沙盒）是两个页面 | 「在项目里干活」被拆成「聊天」+「管理」两处 |
| **Dashboard 是报表不是工作台** | 统计报表（消息数/token/成本） | 用户打开先看报表，而非「进入我的项目」 |
| **环境状态对用户不可见/不可理解** | 沙盒状态只在管理页（运行中/已停止/终止） | 「AI 为什么变慢了/文件在哪」无答案 |
| **AI 工作过程展示粗糙** | 工具步骤以折叠文本展示 | 用户看不到「AI 正在干什么」——信任感缺失 |
| **Agent 是管理对象不是能力成员** | Agent 列表/详情重管理（配置/技能/版本） | 「雇了谁干活」没有心智——只有「管理机器人」 |

### 1.3 技术债（重构顺带治理）

- Chat.tsx 686 行单体（状态/WS/渲染混在一起）
- Dashboard 多接口拼装无聚合（stats/funnel/tokens/approvals 4 请求）
- 页面级状态重复模式（`let $` + rerender 手写）
- UI 测试仅 3 个页面基线（Login/Settings/AgentDetail），核心流程无保护网

## 二、目标架构：项目空间工作台

```
登录 → 工作台（我的项目空间列表）→ 进入项目空间（一体化工作区）
                                                    │
                    ┌───────────────────────────────┼────────────────────────────┐
                    ▼                               ▼                            ▼
            聊天流（@AI 干活）               交付物（文件浏览器）           项目设置（成员/环境/配额）
            AI 过程可视化（步骤/工具）        AI 产物下载/上传              AI 能力成员管理
            HITL 审批                        「AI 刚生成了 report.xlsx」    环境状态（用户语言）
```

**信息架构重构原则**：
1. **项目空间（部门）是一级导航**——Agent/沙盒降级为管理入口（能力管理/环境管理），不再是日常主角
2. **一个部门 = 一个页面**——聊天 + 交付物 + 成员 + 环境状态合一（Chat × DepartmentDetail 合并）
3. **环境状态用户语言化**——「AI 随时能干活 / AI 休息中，干活时自动唤醒」替代「运行中/已停止」
4. **工作台替代报表**——Dashboard 变为「我的项目 + AI 协作动态」，报表降级为运营视角（管理员）

## 六、决策记录

1. **项目空间（部门）是一级导航**——Agent/沙盒收进管理组：日常用户路径不出现技术概念
2. **一个部门 = 一个页面**（聊天×部门详情合并）——文件/成员/环境/聊天同一上下文
3. **环境状态用户语言化**——API 输出 `envStatus` 语义（ready/cold/working/error）+ 文案，前端零翻译
4. **Dashboard 降级为工作台**——报表拆出为运营页（管理员可见）：用户首屏是「我的项目」不是报表
5. **Chat 拆分是硬要求**（686 行 → <300 行组件集）——与功能重构同步，不欠技术债
6. **聚合 API 只读**——写操作仍走现有资源 API（messages/files/sandboxes），聚合层不引入新的写语义
7. **旧路由兼容**（chat/:id 重定向到项目空间）——存量用户书签/链接不失效
