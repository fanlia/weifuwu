# plan —— weifuwu 计划写作规范

> **本目录的规则**：只放**进行中**的计划（每计划一个文件）。计划完成 → 按
> 本文件 §5 收尾（计划归档到 git 历史——工作区不保留完成态计划）。
> **模板**：直接复制「§2 结构模板」新建文件。
> **为什么**：代码即文档——计划是「为什么这么做」的**过程记录**，不是
> 常驻规范——规则生效后并入 docs/client.md / docs/server.md / AGENTS.md。

## 1. 何时写 Plan

- **需要**：缺口驱动（消费侧手搓=框架缺口）、跨文件重构、核心层改动前的
  探针-波次规划（批量工作，一个 Plan 一个主题，波次间独立可验收）
- **不需要**：单文件小修复（直接改 + 契约测试）、无证据的臆想功能（判负：
  一句说明记录在案即可——不建 Plan 不造仪式）

## 2. 结构模板

```md
# <编号> <主题>（<日期>）

> 一句话目标 + 动机（**消费证据/探针数据**——没有证据的计划不立项）。

## 现状探针（先读数）

（一次性探针脚本 /tmp/*.ts 输出的基线——数字是锚点不是观点）

## 波次

| 波次 | 内容 | 验收 |
| --- | --- | --- |
| W1 | （每波次闭环：实现→契约→回归门→commit） | （可运行断言） |

## 判负记录（可被新论证推翻）

- 不做 X：因为 Y —— 推翻条件 Z

## 执行实录（边做边记）

（探针重定位/波次结果/回归数字——**计划的价值在实录**）

## 验收标准

（可勾选清单——全部满足才收尾）
```

## 3. 纪律（写 Plan 的四条）

1. **探针实证先于计划** — 写 Plan 前先跑探针读数。**缺口常被重定位**
   （登记的缺口可能已解决/比想象严重/更轻）——探针是基线锚点。
2. **波次推进** — 每波次独立可回退、不跨波次欠账；回归门先行（fuzz/契约
   防线建在重构之前——对账器保护下才动手术）。
3. **fuzz/对账防线** — 涉及引擎的做法：参考世界 vs 模拟世界终态等价，
   多种子（≥5）× 大样本（≥200 对）；抓到不等价 = 人工甄别（都修单源）。
4. **判负文化** — 启发式误报 >30% 判负；收益不明判负；判负必须登记
   （为什么/替代方案/推翻条件）。

## 4. 计划的验收（呼应模板）

```
□ 探针数据齐全（数字锚点）
□ 每波次独立验收（红/绿可判定）
□ 判负记录写了为什么
□ 执行实录记录了结果数字
□ 全量回归门绿（契约+场景+showcase+server+shared + audit 七线）
```

## 5. 完成收尾

1. 生效规则 → 并入对应文档（docs/client.md / server.md / AGENTS.md——不重复维护）
2. 计划文件 → 融入 git 历史（本目录只留进行中——**历史计划不再物理保留**）
3. 发布版本文档记录（CHANGELOG 登记）

> 历史计划的参考价值由 git log 承接（`git log --follow -- <file>` 可追溯全部过程）。
