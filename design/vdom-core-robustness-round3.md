## 1. 组件树 fuzz 实证（/tmp/comp-fuzz.ts——89% 不等价）

生成器：组件工厂输出形态随机（数组多根/单元素/空洞切换/输出组件）——
嵌套深度 ≤2——种子 11/99 × 150 对。

**样本证据（S_INST 面——实例注册表错乱为主）**：

| 样本 | 参考（build new） | 实际（diff 后） | 差异面 |
| --- | --- | --- | --- |
| seed=99 i=0 | `div > [b, b]` INST: root.0,root.0.0,root.1 | `div > [div>x, b]` INST: root.0,root.0.0,root.0.0.0,root.1 | DOM 层级 + 实例 id |
| seed=11 s1 | `span > span > [div×3]` INST: 6 实例 | （未打印——不等价） | S_INST |
| seed=11 s3 | `div > [div.0.0.0 > x, span > div...]` INST: 4 | （未打印） | DOM + S_INST |

**共性观察**：
- **组件输出组件特判（outIsComponent——compId.0 id 空间）在 diff 对照
  路径错位**——输出组件的实例 id（compId.0）与对照用的槽位 id
  （pathId(parent, i)）不一致——diffSame/transition 按槽位 id 查 registry
  拿不到旧实例——类型检查/区间清理失效
- **组件输出数组（多根）在 diff 的 keyed/混合路径**——数组项的 keyed
  组件 compId 与静态展开的对照路径不一致

## 3. 修复计划（组件路径类级修复）

### P-C1：组件树 fuzz 入仓（先红——基线 89%）

- `reconcile.test.ts` 新增组件 fuzz 轮（生成器：组件工厂输出形态随机
  数组/元素/空洞/输出组件 + keyed 组件 + 嵌套——种子 11/99/7 × 200 对）
- 先跑红（89%）——记录基线——修复后归零

### P-C2：组件实例 id 空间统一（outIsComponent 特判歼灭——核心）

**根因（第 9.1 节诊断的实证）**：组件输出组件时 sink 用 `compId` 作
parent（compId.0 id 空间）——与"组件输出挂槽位 id"的锚点法不一致——
diff 对照（diffSame/emitWithKey/transitionComponent）按槽位 id 查
registry——输出组件的实例注册在 compId.0——**查不到旧实例——类型检查/
区间清理/复用全部失效**。

**修复方向**（二选一——按理论定）：
- **A（消除特判——推荐）**：组件输出组件时与输出元素同规则——挂槽位 id
  （输出组件的 id = 组件自身槽位 id 的展开——与输出数组一致）——需要
  "组件输出组件"的 compId 与 DOM 槽位 id 映射统一（组件输出的子组件
  实例注册在"展开槽位 id"下——区间语义——与输出数组平铺完全一致）
- B（保守）：保留特判但 diff 路径按 compId.0 规则查表（四处对照点
  统一）——特判保留即漂移风险保留

**验收**：组件 fuzz 不等价率大幅下降（目标归零）——S_INST 面与 DOM 区间
同构（三面联动不变量恢复）。

### P-C3：组件输出数组在 keyed/混合路径的 compId 规则统一

- 输出数组项的 keyed 组件 compId = `${parent}.k{key}`（parent = 组件
  输出容器——与静态展开一致）——审计 emitWithKey/removeVNodeTree 的
  compId 计算（cleanup 的 parent 参数语义已对齐——验证 keyed 组件在
  数组内的对照路径）

### P-C4：转换表覆盖度量

- 状态机迁移用例扩展：6×6 转换表的**每个异态对**（text/hole/element/
  component/fragment × 异态）在 fuzz/固定用例中至少触发一次——机器可查
  （计数器断言——转换函数调用统计）

### P-C5：双树对账（id 归属互斥——补充维度）

- Sim 升级：影子树槽位序列 vs DOM 实际 id 序列逐一对照（每槽位 id 唯一
  且与展开序列一致）——补"id 冲突被结构巧合掩盖"盲区（用例 2 变绿之谜
  ——b 与 button 同 id 场景）

## 5. 风险与边界（诚实裁剪）

- **组件 fuzz 的生成器形态**：工厂输出由 kind 决定（无内部状态/无
  ctx.render 异步）——覆盖"输出形态切换"而非"状态更新"——后者由
  场景层/组件测试兜底
- **outIsComponent 特判歼灭（C2-A）**是核心重构——可能牵动
  diffSame/emitWithKey/transitionComponent/removeVNodeTree 的 id 计算——
  每步以组件 fuzz 不等价率下降为验收（先红基线 → 渐绿）
- 不触碰：hooks 状态机（组件内部——场景层兜底）、渲染队列/redirect、
  SSR 吸收策略
- 修复顺序：C1（fuzz 入仓基线）→ C2（特判歼灭——主修复）→ C3 → C4/C5
  （度量/对账维度）
