# agent-builder 计划——Agent 世界模拟平台（2027-03 定稿）

> **定位**：一个"可对话的 agent 世界"平台——把现实问题（调研/推演/模拟/预演/交付）
> 抽象成一个有角色、有关系、有事件的世界，让世界自己运行出结果，并允许用户随时
> 走进世界与任何角色对话。
>
> **一句话**：不卖 agent——卖"用 agent 世界预演决策后果 + 组织虚拟团队交付"。

---

## 1. 本质模型

四个应用场景（问卷/名著推演/公司模拟/城市模拟）是同一件事：

```
现实问题（要决策/要创作/要收集）
   → 抽象为世界（agents + 关系 + 规则 + 蓝本数据）
   → 注入事件，推进回合（agents 交互 → 涌现）
   → 观察记录（叙事/指标/报告）
   → 回到现实：决策依据 / 创作灵感 / 数据结论
```

**本质**：把现实问题抽象成一个可运行的 agent 世界，用世界的涌现结果预演决策后果。
agents 是现实的"认知替身"——模拟是"可能性空间的探索"——不是任务执行。

### 四根支柱（产品必须建立于其上）

| 支柱 | 含义 |
| --- | --- |
| 世界是一等公民 | 不是任务/群聊/看板——是**世界**（身份+关系+规则+状态）——任务只是世界里的一个事件 |
| 交互产生价值（涌现） | 结果不可预编程——agents 互动的涌现才是价值（黛玉之死有千种写法、裁员有连锁反应） |
| 观察是目的 | 模拟的价值 = 可回溯的记录（谁说了什么/为什么/结果如何）——不是"跑完" |
| 预演是用途 | 模拟为了回到现实的决策——政府政策/公司裁员/创作者续写 |

### 产品哲学（诚实边界——写进基因）

1. 模拟产出"可能性"，不是"预测"——报告标注假设与局限
2. 价值在视角多样性——答案的价值 = 视角样本，不是唯一正确
3. 世界永远可回溯——每一步交互记录——决策可辩护
4. 分辨率可调——个体 LLM（准确但贵）→ 代表原型（平衡）→ 宏观方程（快）

## 2. 核心概念（六个一等公民）

```
① 世界（World）——最小单元：持续存在的虚拟空间（角色+关系+历史）
② Agent（角色/居民）——身份档案（人设/立场/风格）+ 记忆（所见所闻）
③ 关系（Relation）——角色之间的边（爱情/亲情/主仆/汇报/同盟/竞争）——图谱可视化
④ 事件（Event）——驱动力：外部注入（问卷派发/市场下滑/政策）或内部产生
⑤ 回合（Turn）——运行单位：激活的角色交互（对话/行动/决策）——调度器编排
⑥ 记录（Record）——一切可回溯：每个回合输入输出/言行/因果
```

### 身份 × 能力（正交——agent = who + can do）

```
身份（who）：立场/风格/关系/记忆——人物/职业/组织/群体代表/系统角色
能力（can do）：手段/产物——可插拔工具集

能力注册表（capabilities）：
  speak   默认（LLM 对话）——所有 agent
  browse  浏览器操作（agent-browser）——填表/调研/试用
  code    编码（read/write/edit/bash/git/run-tests）——coding agent 形态
  file    文件读写/文档/数据处理
  analyze 数据聚合/报告生成
  + 自定义注册（开发者扩展任意能力）

同一身份可配不同能力：财务小王 + browse → 填问卷；+ code → 写财务脚本
coding agent 只是能力谱系的一种形态——世界是"身份 × 能力"的组合空间
```

## 3. 调度模式（同一引擎——规则切换）

| 模式 | 关系 | 时间 | 交互 | 场景 |
| --- | --- | --- | --- | --- |
| 批处理 | 无（独立） | 一次性 | 广播→独立执行 | 问卷/数据收集 |
| 叙事 | 人物图谱（情感边） | 线性 | 回合对话 | 名著推演/剧本/历史重演 |
| 经营 | 组织树（汇报边） | 周期 | 行动/决策/汇报 | 公司模拟/决策推演/组织诊断 |
| 城市 | 社会结构 + 宏观方程 | 周期+宏观 | 代表原型 + 方程 | 政策模拟/城市规划 |

### 缩放法则（核心规律）

```
池规模          形态                     活跃方式
2-50           全 LLM agents             全部活跃（个体）
50-2000        池管理 + 惰性激活          事件相关子集（5-50）
10万-100万     分层：宏观方程 + 代表原型   原型子集（5-30）+ 方程全量

法则：池 = 管理问题（建档/模板/加权）——活跃永远小规模（成本与质量可控）
      个体异质性 = 原型内参数随机化（规则/模板——非全 LLM）
```

### 沟通三通道 + 汇报流

```
广播（指挥官 → 池）——问卷派发/全员指令
定向（指挥官 ⇄ 单 agent）——随时对话（咨询不改世界 / 干预成为新事件）
网格（agent ⇄ agent——调度器编排回合）——推演对话/团队协作
汇报流（agent → 指挥官——周期）——经营/城市模式
```

## 4. 产品形态

### 信息架构

```
世界列表（首页——我的世界卡片：名称/类型徽标/角色数/最近事件/状态）
世界工作区（三区布局——核心界面）
  左：世界侧栏——概览 / 角色（档案/能力/状态）/ 关系（图谱）/ 事件 / 记录
  中：运行控制台——事件注入 / 回合推进 / 叙事流（实时滚动）
  右：观察台——进度看板（x/N + 失败重试）/ 产物（答案/代码/文档/报告）/ 对话
角色详情（抽屉）——身份档案 / 记忆 / 产物 / 对话
世界构建器（新建引导）——选模板 → 加角色（人设池+能力勾选）→ 画关系（图谱）
  → 注入蓝本 → 发布
```

### 三种用户

```
构建者：建世界/配角色/画关系/定能力
指挥官：派事件/推进回合/观察/对话（主用户）
旁观者：只读链接看记录/报告
```

### 特色交互

```
世界 = 持续存在（打开 = 打开活的空间——不是任务）
随时对话（人机混合——咨询/干预两种模式——对话写入记忆影响后续行为）
图谱即界面（RelationGraph——点击角色/拖拽连线）
叙事流 = 时间线（回合记录实时滚动——全部可回溯）
能力徽标（角色卡片显示 🗣️/🌐/💻/📄——知道 ta 能干什么）
```

## 5. 场景走查：10 个 agents 填问卷

```
① 建世界（10 分钟）：选「用户调研」模板 → 自动 10 角色（人设+浏览能力）
② 派发（5 分钟）：粘贴问卷 URL → 勾选 → 开始——叙事流实时滚动
   （每个角色：打开问卷→读题→作答→提交→验证——1-3 秒一条状态）
③ 观察（10 分钟）：10/10 已提交 + 视角分布（财务低分 vs 市场高分）
   + 失败重试（单个角色）——【对话】问财务小王"为什么打 2 分？"——得到解释
④ 导出：答案 CSV + 对话记录 + 分布报告——可回溯可辩护
⑤ 复用：同一世界下次直接派发——角色记得上次立场——越用越准

价值：填表是入口——视角的解释与复用是产品真正的价值
```

## 6. 架构与数据模型

### 数据模型（初版）

```sql
worlds          id, name, type(调研/推演/经营/城市), status, config(调度参数), created_at
agents          id, world_id, name, persona(身份档案), capabilities(json 能力清单),
                status(idle/busy), memory(记忆摘要), stats(任务数/成功率), weight
relations       id, world_id, from_agent, to_agent, type(爱情/汇报/同盟...), strength, directed
events          id, world_id, type(survey/plot/policy/action), payload(json: url/描述/目标),
                status, created_at
turns           id, event_id, agent_id, kind(对话/行动/决策), input, output, ts
records         id, world_id, turn_id, content(叙事/报告), kind, created_at
```

### 运行时

```
调度器：队列 + 槽（批处理）/ 回合编排（叙事）/ 周期步进（经营/城市）——DB 驱动重启可恢复
执行底座：weifuwu ai（createAgent——systemPrompt=身份档案+记忆注入 + AgentTool 工具系统
          + wf: 协议事件流——runToResult 结构化结果）——每角色一个实例
能力执行：browse → agent-browser（会话池——浏览器农场——K Chromium × M context）
          code → 沙盒工作目录（read/write/bash/git——AgentTool）
          analyze → LLM + 数据管道
惰性激活：事件 → 相关角色激活（5-15 个）→ 回合 → 记录 → 休眠
限流预算：LLM 令牌桶 + 每世界/每事件 token 上限 + 失败重试（指数退避）
波次礼仪：大规模批处理（>200）波次滚动 + 随机延迟（被填方承受力）
```

### 与 weifuwu 的能力对照（已评估——足够）

| 需求 | weifuwu | 状态 |
| --- | --- | --- |
| serve/Router/db/queue/scheduler/messager/user | ✓ | 全有 |
| LLM agent 执行底座 | ai（createAgent + AgentTool + wf 协议） | ✓✓（框架最强处） |
| UI | UIRouter/uiServe + 157+ 组件 + hooks | ✓ |
| 关系可视化 | RelationGraph（已沉淀） | ✓ |
| 应用壳/文件树 | AppShell/FileTree（已沉淀） | ✓ |
| 浏览器农场/宏观方程/回合编排 | —— | 业务自研（产品价值本体） |

## 7. 商业模式

### 销售形态（可行性评级）

| 形态 | 卖什么 | 可行性 |
| --- | --- | --- |
| 数字员工订阅 | agent 席位/月（专属知识+历史） | 中（大厂红海） |
| 世界场景包 | 预建世界（红楼包/城市包/行业调研包） | 高（差异化蓝海） |
| 结果服务（项目制） | 推演报告/决策模拟 | 高（政府/企业预算友好） |
| 平台订阅（按量） | 世界构建器 + 运行时 | 中（竞争激烈） |

**裸 agent 不可行**（信息商品——复制零成本）——卖"世界 + 结果 + 对话"。

### 定位差异

```
大厂 agent 平台 = 工具（干一件事）
世界模型 = 认知替身 + 行动替身（预演后果 + 虚拟团队交付）
销售单元 = 世界场景 + 代表 agents + 决策报告 + 随时对话
```

### 起步路径

```
结果服务验证付费意愿 → 场景包产品化 → 平台订阅规模化
商业骨架复用 agent-platform 已实现（租户/配额/订阅/BYOK/白标）
```

## 8. 对开发者的价值（对比 coding agent）

```
coding agent：供给侧——代码怎么写（对象：代码库）
世界模型式：需求侧——系统/用户/业务会怎么反应（对象：角色世界）

组合闭环：世界模型给"做什么"的证据 → coding agent 写实现
   "模拟显示 60% 用户对 X 功能困惑——请重构引导" → Cursor/Claude Code 写代码
   ——手需要眼睛才知道往哪写

开发者用世界模型：需求验证（用户反应模拟）/ 产品模拟（定价/竞对）/
  应用用户模拟测试（漏斗/留存/UX 痛点）/ 自举（模拟框架用户对组件的反应）
```

## 9. 落地路线

```
Phase 0  ✅ 定稿（本文档）
Phase 1  世界数据模型 + API：worlds/agents/relations/events CRUD
Phase 2  回合引擎（叙事模式最小）：事件注入 → 激活 → 对话回合 → 记录
Phase 3  UI：世界构建器（图谱+档案）→ 运行控制台 → 观察台
Phase 4  场景验证：红楼梦小世界（5-8 人物推演 3-5 回合）——验证本质抽象
Phase 5  横向铺：批处理（问卷）→ 经营（公司）→ 能力注入（browse→code）
```

### 最小闭环验收标准

```
建一个 5 人物世界（RelationGraph 可视化）→ 注入事件（"元春省亲"）
→ 相关人物激活 → 每人一个对话回合（AI 按人设作答）→ 叙事记录可回溯
→ 与任意人物随时对话（定向通道）——全流程零自定义组件
```
