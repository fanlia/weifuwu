# weifuwu 计划目录（Plans）

> 全部在途计划的索引——目标体系 + 优先级 + 依赖关系。
> 每个子计划：目标（验收标准）· 任务清单 · 优先级 · 依赖 · 状态。
> 与 showcase-plan.md（已完成的 P0-P4）衔接：本目录是**下一阶段**（生态与体验）。

## 目标体系（一句话）

```
weifuwu 从"高质量仓库"成为"可生存、可增长、可感知的开源项目"——
成熟是过程不是里程碑：每轮真实反馈 → 演进 → 再反馈（0.x 快速迭代 + 弃用纪律，
1.0 由市场定义不由日历定义）：
  ① 生态：可被发现、被采用、被贡献（npm/落地页/贡献入口）
  ② 体验：需求驱动的学习阶梯（零基础 → 复杂应用无断层）
  ③ 治理：组件库质量可审计、去留可决策（补全/合并/重划）
  ④ 设计：有独特面孔的设计语言（微流明）+ 专业感（眼前一亮）
  ⑤ 平台：showcase = 生态搭建器（外网落地 + 承载生态）
```

## 依赖关系

```
01 生态 ← 05 落地页（案例墙素材）· ← 03 治理（发布前组件定稿）
```

## 执行顺序建议

```
第一批（地基，2 周）：03 缺失补全 A 组 → 04 设计语言 2.0 → 05 PORT+SSR → 01 发布+C 贡献指南

第三批（生态，持续）：01 案例墙/community → 02 分类重划/纪律 → 03 合并决策 → 04 校准
```
